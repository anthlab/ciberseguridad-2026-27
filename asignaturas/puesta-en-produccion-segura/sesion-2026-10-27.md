# PPS · 27/10/2026 · Práctica 2: código seguro

**Meta:** reconocer la entrada de datos y los *sinks* peligrosos, demostrar un defecto mediante un test de regresión, corregirlo y complementar las pruebas con fuzzing.

## Secuencia de trabajo (4 horas, propuesta)

1. **0-15 min:** recuperación de Git y Docker y explicación de la regla: una corrección necesita una prueba que falle antes y pase después.
2. **15-55 min:** preparar un entorno virtual de Python, descargar el ZIP de Drive, localizar las entradas y *sinks* en Python, Java y C. Ejecutar solo las entradas de prueba inofensivas indicadas.
3. **55-105 min:** ejecutar la batería existente, medir cobertura e identificar por qué no detecta la incidencia 17.
4. **105-120 min:** pausa y resolución de bloqueos.
5. **120-170 min:** añadir `test_regresion_incidencia_17`; comprobar que falla frente al código inicial, corregir `aplicar_descuento` y repetir `pytest`.
6. **170-205 min:** ejecutar `fuzz_casero.py` con 20.000 combinaciones; definir el invariante de resultado válido; corregir casos límites y añadir una prueba nueva.
7. **205-230 min:** comprobar `git status`, excluir `.venv/`, registrar evidencias, hacer commit y push al repositorio individual.
8. **230-240 min:** repaso tipo Kahoot sobre Git, GitHub y Docker y cierre.
