PPS · Apuntes de Git, GitHub y Docker

Apuntes para después de la práctica. Objetivo: conservar y compartir una web con historial y ejecutarla en un contenedor. El proyecto-final incluido es una referencia; conserva tus propios commits y evidencias.

1. Tres herramientas, tres funciones

HerramientaPara qué la usamos
GitGuardar versiones y trabajar con ramas en el equipo.
GitHubAlojar el repositorio remoto y proponer/revisar cambios con pull requests.
DockerConstruir una imagen con el entorno y crear contenedores a partir de ella.

2. Primer historial local

Abre terminal en la carpeta del proyecto y configura tu nombre y correo de commits solo allí. Sustituye los valores de ejemplo. El correo noreply está en Settings → Emails de GitHub.

git init -b main
git config --local user.name "Alumno NN"
git config --local user.email "TU_CORREO_NOREPLY_DE_GITHUB"
git status
git add index.html .gitignore .dockerignore LEEME.txt
git diff --cached
git commit -m "Crea la pagina inicial de PPS"
git log --oneline

git status muestra estado; git diff muestra cambios sin preparar; git add selecciona lo que entra en el próximo commit; git diff --cached permite revisarlo; commit registra localmente. Guardar un archivo en el editor no crea un commit.

3. Publicar en GitHub

Crea en la web un repositorio privado vacío llamado pps-arranque. No añadas README si tu repositorio local ya tiene commits. Con gh previamente instalado:

gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
git remote add origin https://github.com/TU_USUARIO/pps-arranque.git
git push -u origin main

La autenticación usa el navegador. No publiques tokens ni claves. origin es un nombre para la dirección remota; push envía commits. El profesor necesita acceso explícito para ver un repositorio privado.

4. Proponer e integrar un cambio

Crea la rama, modifica index.html y luego ejecuta diff, add, commit y push:

git switch -c mejora-portada
git diff
git add index.html
git commit -m "Personaliza la portada del aula"
git push -u origin mejora-portada

En GitHub crea una PR de mejora-portada hacia main. Revisa Files changed, describe la modificación y cómo la has comprobado, y fusiónala tras la revisión. Actualiza tu main local:

git switch main
git pull --ff-only origin main
git log --oneline --graph --all

pull --ff-only se detiene si las historias divergen; no fuerces el push para resolverlo. Pide ayuda e inspecciona el historial.

5. Dockerfile completo

FROM python:3.12-slim
WORKDIR /app
COPY index.html .
USER 10001:10001
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000", "--bind", "0.0.0.0"]

FROM selecciona la base; WORKDIR establece el directorio; COPY incorpora la página; USER ejecuta con usuario no root; EXPOSE documenta el puerto; CMD define el proceso. El servidor escucha dentro del contenedor en 0.0.0.0. Es una web de laboratorio, no un servidor de producción.

6. Construir y ejecutar

docker build -t pps-web:v1 .
docker run -d --name pps-s01-web -p 127.0.0.1:8080:8000 pps-web:v1
docker ps
docker logs pps-s01-web

Abre http://127.0.0.1:8080. Imagen: plantilla del entorno y archivos. Contenedor: instancia creada desde esa imagen. El proceso principal sirve la web; si termina, se detiene el contenedor. Los logs muestran las peticiones cuando visitas la página.

7. Actualizar la web

Edita Version 1 → Version 2 en el archivo. El contenedor no cambia automáticamente. Versiona el cambio, construye otra imagen y recrea el contenedor:

git add index.html
git commit -m "Actualiza la pagina a version 2"
git push
docker build -t pps-web:v2 .
docker stop pps-s01-web
docker rm pps-s01-web
docker run -d --name pps-s01-web -p 127.0.0.1:8080:8000 pps-web:v2

git push guarda el cambio remoto; no despliega. docker build construye; no sustituye contenedores existentes. docker restart reinicia el mismo contenedor; no lo actualiza a una imagen distinta. Eliminar el contenedor de esta práctica no elimina las imágenes.

8. Comandos de consulta y parada

docker image ls
docker ps
docker ps -a
docker logs pps-s01-web
docker stop pps-s01-web
docker start pps-s01-web

Al acabar puedes dejarlo parado con stop. No uses limpiezas globales para esta práctica. .gitignore excluye archivos nuevos del seguimiento; no elimina secretos ya subidos. .dockerignore limita el contexto de build y es independiente de Git.

9. Diagnóstico rápido

ProblemaQué comprobar
Git pide identidadConfigurar user.name y user.email dentro del repositorio.
origin already existsgit remote -v; no volver a añadir el mismo remoto.
Push rechazadoCuenta, permisos, URL y si el remoto se creó vacío. No usar force.
Docker permission denied / no ServerMotor y permisos deben estar preparados; avisar al docente.
Puerto ocupadoPublicar 8081:8000 y abrir 8081.
Nombre ocupadoMirar docker ps -a; usar un nombre propio distinto.
Sigue Version 1Comprobar archivo guardado, build v2, nuevo contenedor y refresco sin caché.
No se descarga la baseUsar la imagen precargada por el docente; sin ella se necesita red.

10. Qué viene después

Primero repetir este ciclo sin copiar cada comando. Después integrar pruebas y regresiones en el repositorio, añadir Compose cuando haya varios servicios, y más adelante CI, análisis de seguridad y despliegue. Haber hecho una PR hoy no equivale a completar DevSecOps.
