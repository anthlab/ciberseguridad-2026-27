PPS · Reto de consolidación: GitHub y Docker

Práctica de consolidación tras la primera demostración de Git, GitHub y Docker. La meta no es copiar una receta: reproduce el ciclo, explica cada decisión y resuelve una variación. Mantén el repositorio privado; nunca compartas contraseñas, tokens ni códigos de acceso.

Reto A · Git y GitHub sin saltarse pasos

  1. Clona tu propio repositorio privado en una carpeta nueva; comprueba con status, branch y log qué tienes antes de tocar nada.
  2. Crea una rama para personalizar el encabezado y el texto de la página. Antes de guardar el commit, inspecciona el diff y el contenido preparado.
  3. Publica la rama y abre una pull request hacia main. Explica qué cambiaste y cómo lo comprobaste. Pide a tu pareja (invitada como colaboradora) que revise una línea; responde a la observación antes del merge.
  4. Actualiza main y muestra el grafo del historial. Identifica qué cambio quedó en local, cuál llegó a GitHub y cuál se integró.

Reto B · Docker y versiones

  1. Antes de construir, señala en el Dockerfile la imagen base, el directorio, el archivo que se copia, el usuario, el puerto del contenedor y el proceso principal.
  2. Construye la versión de la web que tienes ahora. Ejecuta el contenedor con el puerto del equipo enlazado solo a localhost; verifica el sitio en el navegador y una petición en los logs.
  3. Con el contenedor activo, cambia el texto visible de Version 2 a Version 3. Predice el resultado antes de refrescar. Anota por qué editar el archivo y reiniciar el contenedor no actualizan lo que ya se copió a la imagen.
  4. Guarda ese cambio en Git y en GitHub; construye una imagen con una etiqueta nueva y crea otro contenedor en un puerto local distinto. Compara Version 2 y Version 3, el mapeo de puertos y sus logs.
  5. Desde un clon limpio, construye la imagen de nuevo y comprueba que obtienes Version 3. Para terminar, detén solo los contenedores de este reto.

Entrega individual

  • URL del repositorio privado y de la pull request fusionada (el profesor debe tener acceso).
  • Historial con al menos tres commits comprensibles y la rama integrada.
  • Captura o comprobación del sitio en dos versiones, mapeos de puerto y logs.
  • Explicación propia: qué hace commit, push, merge, build, run y restart; por qué la imagen no cambia al editar un archivo.
  • Una dificultad encontrada, el dato usado para diagnosticarla y la solución verificada. Sin capturas con información sensible.

Si algo falla

No uses force push, no hagas público el repositorio y no ejecutes limpiezas globales de Docker. Si el puerto no abre, comprueba estado, puerto publicado, logs y URL; si ves la versión antigua, comprueba etiqueta de imagen y contenedor activo. Pide una pista concreta y vuelve a demostrarlo tú.
