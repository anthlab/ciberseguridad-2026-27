PPS · Práctica 1: Git, GitHub y Docker

Sigue la demostración paso a paso. Después de cada operación, comprueba el resultado y anota qué cambió. No compartas contraseñas, tokens ni códigos de acceso; el repositorio debe permanecer privado.

1. Guardar versiones

  1. Extrae el proyecto inicial y abre una terminal en la carpeta con index.html.
  2. Comprueba git --version, docker version y gh --version. Si Docker no muestra cliente y servidor, avisa al profesor.
  3. Inicializa Git en main y configura nombre/correo solo para este repositorio. Revisa el estado antes de añadir archivos.
  4. Añade index.html, .gitignore, .dockerignore y LEEME.txt. Revisa git diff --cached, crea el primer commit y comprueba git log --oneline.
  5. Cambia una línea de LEEME.txt; revisa git diff, añade solo ese archivo y crea un segundo commit.

2. Publicar y revisar

  1. Crea un repositorio GitHub privado y vacío llamado pps-arranque; conecta tu copia y publica main.
  2. Crea la rama mejora-portada, modifica el título de la página y publica la rama.
  3. Abre una pull request hacia main. Revisa Files changed, incorpora una observación del profesor o compañero y fusiona la PR. Actualiza main local.

3. Construir y ejecutar

  1. Escribe el Dockerfile siguiendo la demostración. Identifica qué aporta la imagen base, qué copia COPY y qué hace el comando de arranque.
  2. Construye la imagen pps-web:v1. Añade el Dockerfile a Git, crea un commit y publícalo.
  3. Ejecuta un contenedor con nombre y puerto libres. Abre la web en localhost; muestra docker ps y docker logs. Distingue el puerto del equipo del puerto del contenedor.
  4. Cambia el texto visible a Version 2. Predice qué ocurrirá. Comprueba que editar el archivo y reiniciar no actualiza la imagen; reconstruye, recrea el contenedor y verifica Version 2.

4. Reproducir y entregar

  1. Clona el repositorio en una carpeta nueva, construye desde esa copia y comprueba la versión.
  2. Completa ficha-entrega.txt. Entrega URL privada del repo y de la PR, historial, captura del sitio y los logs, y tus respuestas.

Comprueba que puedes explicar

  • Diferencia entre commit, push, pull request y merge.
  • Diferencia entre imagen y contenedor; entre build, run y restart.
  • Por qué editar un archivo no cambia el contenedor hasta reconstruir y crearlo de nuevo.
  • Qué información aportan git status, git log, docker ps y docker logs.

Si algo falla, registra el mensaje, predice una causa y comprueba una cosa cada vez. No hagas público el repositorio ni elimines contenedores ajenos.
